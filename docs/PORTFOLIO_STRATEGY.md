# hrniux 公开作品规划

规划日期：2026-10-25。本文描述拟执行的 30/60/90 天目标，不代表这些目标已经完成。参考依据见 [RESEARCH.md](RESEARCH.md)。范围仅为公开作品。

## 定位与读者

主线是 **Java/Spring 后端与可解释 Agent 工程实践**。RAG、MCP 与 Mac 是具体技术或开发环境，应通过项目用途、关键源码和可复现步骤说明，不扩写为未经证实的资历。

主要读者是想运行项目的开发者、评估工程能力的协作者，以及寻找具体技术实践的人。主页让他们快速进入代表作，项目 README 让他们完成首次运行，实践记录解释设计取舍与验证结果。

## 主页与 README 的可实施结构

主页采用一句定位、简短导航、三个核心项目、其他作品、真实实践记录。每个项目写一句用途和一个明确入口；有真实运行或发布记录再加入带日期的成果。原创新视觉只作为识别辅助。

项目 README 使用以下顺序：

1. 解决的问题、适合的读者与当前状态。
2. 最小输入与可观察输出；截图必须来自实际运行。
3. 前置条件、配置、启动命令与首次验证步骤。
4. 架构或决策流程，以及关键源码入口。
5. 测试、复现结果、数据或环境来源。
6. 已知限制、实验分支与待办计划。

记录固定为“问题 → 做法 → 证据 → 下一步”。每篇连接相关源码、PR 或运行记录；以实际发表时间标日期。没有来源的数字、粉丝规模、任职经历、商业落地和社区反馈不进入文档。

## GitHub Studio 的角色与权限现实

GitHub Studio 维护公开仓库事实、主页源码、操作计划与执行结果。命令文档需清楚区分只读的 `plan`/`status` 与显式写入的 `apply`，并以实际实现及验证输出为准。

独立仓库创建请求遇到 403。当前承载位置是 [hrniux/hrniux 的 github-studio 分支](https://github.com/hrniux/hrniux/tree/github-studio)，不能对外宣称新仓库已经创建。权限恢复后拟执行：创建公开独立仓库、迁移源码与历史或记录来源、验证链接与运行方式、更新主页入口。迁移完成前保留现有分支链接。

配置记录预期值，执行报告记录真实结果。权限失败保留原因和可重试状态；每次写入后读取核对。手动 Pin 和未完成迁移保留为待办。只输出公开仓库信息，不创建定时任务。
